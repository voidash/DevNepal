Handling Bikram Sambat dates in PostgreSQL without losing your mind

ASAarati Shrestha@aarati · Frontend engineer · LalitpurLinked project · NepaliDate.js Community project

Why this is hard

Fiscal years start in mid-July, months run 29 to 32 days and no formula predicts them. Unlike Gregorian arithmetic, Bikram Sambat needs a calendar table — a list of month lengths for every year you intend to support, maintained by hand from the official calendar.

-- sql
CREATE TABLE bs_calendar (
  bs_year  int NOT NULL,
  bs_month int NOT NULL CHECK (bs_month BETWEEN 1 AND 12),
  days     int NOT NULL CHECK (days BETWEEN 29 AND 32),
  ad_start date NOT NULL,
  PRIMARY KEY (bs_year, bs_month)
);

The calendar table

Here are the month lengths for the four years most of us need right now. Note 2081 Jestha: 32 days.

Tests we ship

  • Round-trip every day from 2000-01-01 to 2045-12-31 through AD → BS → AD.
  • Fiscal-year boundary: 1 Shrawan resolves to mid-July in every supported year.
  • The 32-day months exist only where the official calendar says so.

The full implementation, with the calendar data as CSV, is in the NepaliDate.js repository . Corrections welcome — that is what the table is for.
